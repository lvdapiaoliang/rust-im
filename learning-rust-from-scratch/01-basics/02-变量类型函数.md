# 02 - 变量、类型与函数

## 本章目标

掌握 Rust 的变量模型（不可变默认）、基本类型、函数签名。

## 一、变量：默认不可变

```rust
let x = 5;        // 不可变（immutable）——默认！
// x = 6;         // 编译错误
let mut y = 5;    // 可变需要显式 mut
y = 6;            // OK

let z = 5;        // shadowing：同名新变量「遮蔽」旧变量
let z = z + 1;    // 全新的 z，甚至可以是不同类型！
let z = "现在是字符串";
```

> 【Java】Java 的 `final` 要显式写，Rust 反过来：**可变才显式**。
> 好处：读代码时看到 `let` 就知道这个值不会变，代码审查负担骤降。
> shadowing 是 Java 没有的：它允许「转换类型后复用变量名」，
> 比Java 里 `String s2 = s.trim()` 这种 `s2`、`s3` 连环命名干净得多。

### 常量 vs 不可变变量

```rust
const MAX_CONNECTIONS: u32 = 100_000;  // 编译期常量，必须标类型，可放全局
static COUNTER: AtomicU64 = AtomicU64::new(0);  // 全局静态（可变需原子类型）
```

> 【Java】`const` ≈ `static final`；数字里的 `_` 分隔符（`100_000`）与 Java 7+ 相同。

## 二、基本类型

### 整数（没有隐式转换！）

| 长度 | 有符号 | 无符号 |
|------|--------|--------|
| 8 位 | `i8` | `u8` |
| 16 位 | `i16` | `u16` |
| 32 位 | `i32`（默认） | `u32` |
| 64 位 | `i64` | `u64` |
| 平台相关 | `isize` | `usize` |

```rust
let a: i32 = 100;
let b: i64 = 100;
// let c = a + b;        // 编译错误！i32 和 i64 不能直接相加
let c = i64::from(a) + b; // 显式转换（as 也可以：a as i64，但 as 更粗暴）
```

> 【Java】最大思维转变：**Rust 没有隐式类型提升**。
> Java 里 `int + long` 自动提升，Rust 认为这可能掩盖溢出/截断 bug，要求你显式写。
> `usize` 是数组下标类型——所有索引运算都用它，记住这条能少一半报错。

### 浮点、布尔、字符

```rust
let f = 2.5;          // f64（默认，类似 Java 的 double）
let g: f32 = 2.5;     // f32（float）
let flag = true;      // bool
let c = '中';          // char 是 4 字节 Unicode 标量（Java char 是 2 字节 UTF-16！）
let emoji = '🎉';      // Rust char 能存 emoji，Java char 不能（得用 String）
```

> 【Java】`char` 差异是真实的坑：Java 的 char 放不下 emoji（代理对），
> Rust 的 char 是完整 Unicode 码点。字符串遍历时行为也不同（见第 8 篇）。

### 字符串：两种，必须分清

```rust
let s1: &str = "字面量";           // 字符串切片：指向 UTF-8 字节序列的引用
let s2: String = String::from("堆上"); // String：拥有所有权的可增长字符串
let s3 = s2.clone();               // 深拷贝（【Java】str1 == str2 比较的是引用，Rust 比较内容用 ==）
```

> 【Java】对照：`String` ≈ Java `String`（但可变增长，更像 `StringBuilder` 与 `String` 合体）；
> `&str` ≈ `CharSequence` 视图。`s1 == s2` 在 Rust 里**比较内容**（要求 PartialEq），不是引用相等。

### 元组与数组

```rust
let pair: (i32, &str) = (1, "one");
let (num, word) = pair;            // 解构（【Java】没有，record 模式匹配 Java 21 才有）
println!("{} {}", pair.0, pair.1); // .0 .1 访问

let arr: [i32; 3] = [1, 2, 3];     // 定长数组，长度是类型的一部分
let zeros = [0u8; 4096];           // 【实战】echo server 的读缓冲区就是这么写的
```

## 三、函数

```rust
fn add(a: i32, b: i32) -> i32 {    // 必须标参数和返回类型（无类型推断）
    a + b                          // 没有分号！这是「表达式返回」
}

fn early(x: i32) -> i32 {
    if x < 0 {
        return x.abs();            // 提前返回用 return（带分号）
    }
    x * 2                          // 尾表达式作为返回值
}
```

核心概念：**Rust 里 `{}` 块、`if`、`match` 都是表达式**：

```rust
let level = if score > 90 { "A" } else { "B" };   // if 是表达式
```

> 【Java】Java 的 `if` 是语句不是表达式（三元 `?:` 才是），
> Rust 直接把三元运算符废了——`if/else` 本身就能当值用，而且支持多行。

### never 类型 `!`

```rust
fn die() -> ! {         // 永不返回（panic 或无限循环）
    panic!("fatal");
}
```

> 【Java】类比 `System.exit()` 之后的代码路径。编译器知道 `!` 类型的代码不会产生值，
> 所以 `let x = match v { Some(v) => v, None => die() };` 能通过类型检查。

## 练习

1. 写函数 `fizzbuzz(n: u32) -> String`，用 `if/else` 表达式风格（不用 return）。
2. 用 shadowing 实现三次类型转换：`"42"` → `42` → `42.0`。
3. 制造一个 i32 加 i64 的编译错误，分别用 `i64::from()` 和 `as` 修复，思考两者区别（提示：`as` 允许截断，`From` 只允许无损转换）。
