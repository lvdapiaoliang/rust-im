# 01 - 环境与第一个程序

## 本章目标

装好工具链，理解 Cargo（对照 Maven/Gradle），跑通第一个程序，学会看编译器报错。

## 一、安装

Windows 下访问 [rustup.rs](https://rustup.rs) 下载安装，或：

```powershell
winget install Rustlang.Rustup
```

安装完成后验证：

```powershell
rustc --version     # 编译器
cargo --version     # 构建工具 + 包管理器
```

> 【Java】rustup ≈ sdkman + JVM 版本管理；cargo ≈ Maven + Gradle + npm 的合体
> （构建、依赖管理、测试、发布全都是它）。

## 二、Cargo 项目结构

```powershell
cargo new hello          # 生成二进制项目
cd hello
cargo run                # 编译并运行
```

生成的结构：

```
hello/
├── Cargo.toml    # 【Java】pom.xml：包名、版本、依赖
├── Cargo.lock    # 【Java】锁定依赖精确版本（类似 lock 文件，要提交 git）
└── src/
    └── main.rs   # 程序入口
```

`Cargo.toml` 最小示例：

```toml
[package]
name = "hello"
version = "0.1.0"
edition = "2024"

[dependencies]
# 依赖写在 [dependencies]，如 tokio = { version = "1", features = ["full"] }
```

常用命令对照表：

| Cargo | Java 世界对应 |
|-------|---------------|
| `cargo new` | `mvn archetype:generate` |
| `cargo build` | `mvn compile` |
| `cargo build --release` | `mvn package -P prod`（开优化） |
| `cargo run` | `mvn exec:java` |
| `cargo test` | `mvn test` |
| `cargo check` | 只做类型检查不生成产物（比 build 快得多，写代码时用它） |
| `cargo add tokio` | 手动往 pom 加依赖 |
| `cargo doc --open` | 生成并打开本项目+依赖的文档（javadoc） |

## 三、Hello World 逐行解读

```rust
fn main() {
    println!("Hello, world!");
}
```

三个信息：

1. `fn main()` 是入口，没有参数没有返回值（要读命令行参数用 `std::env::args()`）
2. `println!` 带 `!` —— 它是**宏**不是函数。为什么是宏？因为格式化参数的个数/类型在编译期检查，函数做不到（【Java】`System.out.printf` 的类型安全版本）
3. 语句以分号结尾，块用 `{}`，看起来和 Java 很像——这是好事，前两周语法不是重点

格式化打印速查：

```rust
let name = "world";
println!("Hello, {name}");           // 内插（推荐，类似 Java 的文本块插值）
println!("Hello, {}", name);         // 位置参数
println!("{0} 与 {0}", name);        // 复用参数
println!("{:?}", vec![1, 2, 3]);     // 调试打印（{:?} 要求实现 Debug）
eprintln!("错误输出到 stderr");      // 【Java】System.err
```

## 四、最重要的习惯：和编译器做朋友

Rust 编译器报错信息质量极高，**每个错误都带解释和修复建议**。

```powershell
rustc --explain E0382   # 把任何错误码展开成一篇教程
```

> 新手心态建议：Java 程序员看到满屏红色下意识觉得「我菜」；
> Rust 的正确姿势是「编译器在 code review，它在教我」。
> 本系列 02-core 里的所有权错误，全部值得用 `--explain` 读一遍。

## 练习

1. `cargo new playground`，把上面格式化打印的 6 行全部跑一遍。
2. 故意写 `let x: i32 = "hello";`，看编译器报什么，然后 `rustc --explain E0308`。
3. `cargo check` 和 `cargo build` 各跑一次，感受速度差（大项目里 check 快一个数量级）。
