# 09 - 智能指针：Box、Rc、Arc、RefCell

## 本章目标

理解「在堆上放数据」和「绕过借用规则的受控逃生舱」。
本篇是 02-core 里概念密度最高的一篇，也是 Send/Sync（→ docs/02）的前置。

## 一、Box<T>：最简单的堆分配

```rust
let b = Box::new(5);        // 5 放堆上，b 是栈上的胖句柄
```

Box 的三大用途：

```rust
// ① 递归类型（编译器必须知道大小，递归必须断开用 Box）
enum List { Cons(i32, Box<List>), Nil }
// enum List { Cons(i32, List), Nil }   // ❌ 无限大小

// ② 大数据转移所有权时避免栈上拷贝（实际上 move 本身只拷贝栈上部分）

// ③ trait 对象（dyn 的载体）
let shapes: Vec<Box<dyn Shape>> = vec![...];
```

> 【Java】Java 一切对象都在堆上，Box 对你来说最陌生也最简单：
> 它就是「把一个值显式放堆上」，没有 GC 参与，drop 即释放。

## 二、Rc 与 Arc：共享所有权

借用规则说「唯一所有者」，但有时数据就是需要被多方共享（如多个连接共享路由表）：

```rust
use std::rc::Rc;
use std::sync::Arc;

// Rc：单线程引用计数（非原子，快）
let a = Rc::new(vec![1, 2, 3]);
let b = Rc::clone(&a);          // 引用计数 +1（浅拷贝句柄，非数据）
println!("{}", Rc::strong_count(&a));   // 2
drop(b);                         // 计数 -1；归零时数据释放

// Arc：Atomic Rc，多线程安全版
let a = Arc::new(vec![1, 2, 3]);
std::thread::spawn(move || {     // 要求 Send，Rc 不行，Arc 可以
    println!("{}", Arc::strong_count(&a));
});
```

> 【Java】`Arc` ≈ 无 GC 世界里的普通对象引用 + 立即回收的引用计数。
> 与 GC 对比：计数到 0 立即释放（确定性），但**循环引用会泄漏**
> （A→B→A 永远不到 0），需要 `Weak<T>` 打破环——GC 不怕环，Rc/Arc 怕。
> 【实战】rust-im 服务端：`Arc<DashMap<UserId, ...>>` 是每连接 task 共享的路由表。

### Weak：观察者不阻止释放

```rust
use std::rc::{Rc, Weak};
let strong = Rc::new(Session::new());
let weak: Weak<Session> = Rc::downgrade(&strong);   // 弱引用不计入 strong_count
drop(strong);                                       // 数据释放
assert!(weak.upgrade().is_none());                  // 升级失败：对象已死
// 用途：缓存（数据没了缓存自然失效）、子对象引用父对象不造成环
```

## 三、RefCell / Mutex：内部可变性

「不可变引用却能改数据」的受控逃生舱：

```rust
use std::cell::RefCell;
let data = RefCell::new(vec![1, 2]);

{
    let mut w = data.borrow_mut();   // 运行时借用计数：可变借用 +1
    w.push(3);
}                                    // w drop，借用释放

{
    let r1 = data.borrow();
    let r2 = data.borrow();          // ✅ 两个只读
    // let mut w = data.borrow_mut(); // ❌ panic!（运行时检测，非编译期）
}
```

**编译期借用检查 → 运行时借用检查**：规则没变（N 读或 1 写），
只是检查时机从编译挪到运行，违规从编译错误变成 panic。
适用场景：借用结构编译器推不出来的场合（如测试 mock、递归结构里改字段）。

> 【Java】`RefCell` 没有直接对应物，心智上接近「带并发 bug 检测的字段」。
> 一定要记住：**RefCell 不是线程安全工具**，它是单线程的；
> 多线程的对应物是 `Mutex`/`RwLock`（→ 03-tokio/06）。

### Cell：Copy 类型的更轻选择

```rust
use std::cell::Cell;
let c = Cell::new(0);
c.set(5);
let v = c.get();    // 只对 Copy 类型，无借用概念，更快
```

### 组合拳：Rc<RefCell<T>>

单线程里「多处共享 + 可修改」的标准答案（多线程版是 `Arc<Mutex<T>>`）：

```rust
let shared = Rc::new(RefCell::new(0));
let a = Rc::clone(&shared);
*a.borrow_mut() += 1;
```

## 四、Deref 与自动解引用

智能指针能像普通引用一样用的原因：

```rust
let s = String::from("hi");
// String 实现了 Deref<Target=str>，所以 &String 自动转 &str：
fn takes_str(s: &str) {}
takes_str(&s);              // 自动 Deref（编译器插入 deref 链）
// Box/Rc/Arc/RefCell 同理，Deref 链可连续：&Rc<RefCell<T>> → &T
```

这就是「Deref 多态」——也提醒我们：**自定义 Deref 只该给指针语义的类型用**，
滥用会造成隐式转换地狱（和 Java 重载解析地狱一个性质）。

## 五、智能指针选择决策树

```
需要堆上单个值 / 递归 / dyn？ ── 是 → Box<T>
数据会被多处共享？
├─ 单线程 → 需要修改？
│   ├─ 是 → Rc<RefCell<T>>
│   └─ 否 → Rc<T>
└─ 多线程 → 需要修改？
    ├─ 是 → Arc<Mutex<T>>（或 RwLock）
    └─ 否 → Arc<T>
Copy 小值 + 单线程高频改 → Cell<T>
缓存/父子环 → 加 Weak
```

## 六、总表

| 类型 | 所有权 | 线程安全 | 可变性 | 【Java】感觉 |
|------|--------|----------|--------|--------------|
| `Box<T>` | 独占 | Send（若 T） | 随 T | new 到堆上 |
| `Rc<T>` | 共享 | ❌ | 随 T | 普通引用+计数 |
| `Arc<T>` | 共享 | ✅ | 随 T | 线程安全引用 |
| `RefCell<T>` | 独占 | ❌ | 运行时检查 | 带护栏的字段 |
| `Mutex<T>` | 独占 | ✅ | 锁保护 | synchronized |
| `Cow<T>` | 借用或拥有 | 随 T | 克隆时 | copy-on-write |
