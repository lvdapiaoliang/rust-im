# 06 - 所有权、借用与生命周期

> [→ 实战：docs/01-rust-core.md](../../../docs/01-rust-core.md)，

## 本章目标

内化三问：内存何时释放？谁能读写？引用何时失效？
能读懂并修复编译器的借用错误（这是新手 80% 报错的来源）。

## 一、心智模型：从 GC 到所有权

```
Java：  new 出来的对象 → 堆上 → GC 跟踪引用 → 没人用了就回收（时机不确定）
Rust：  值有唯一所有者 → 所有权可转移(move) → 所有者离开作用域 → 立即释放(drop)
```

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;              // move：s1 的所有权交给 s2
    // println!("{s1}");      // ❌ E0382: value borrowed here after move
    println!("{s2}");
}                             // s2 drop，堆内存释放
```

> 【Java】`String s2 = s1` 是两个引用指向同一对象；
> Rust 若允许这样，函数结束时 s1、s2 各释放一次堆内存（double free）。
> Rust 的选择：move 后旧变量静态失效。

### Copy 例外

```rust
let a = 5;
let b = a;        // i32 是 Copy：栈上按位复制，a 仍有效
println!("{a}");  // ✅
```

规则：纯栈数据（数字、bool、char、定长数组/元组且元素均 Copy）自动 Copy；
有堆资源（String/Vec/File/TcpStream）必然 move。

## 二、借用规则

```rust
fn main() {
    let mut v = vec![1, 2, 3];

    let r1 = &v;              // 不可变借用
    let r2 = &v;              // 多个不可变借用 ✅
    println!("{r1:?} {r2:?}");// r1 r2 最后一次使用（NLL：借用到此结束）

    v.push(4);                // ✅ 上面借用已结束，此刻可以可变访问
    // let r3 = &v;
    // v.push(5);             // ❌ E0502: cannot borrow as mutable while borrowed
    // println!("{r3:?}");
}
```

铁律：**任意时刻，要么 N 个 `&T`，要么 1 个 `&mut T`，不能共存**。

NLL（非词法生命周期）：借用的结束点是「最后一次使用」，不是右花括号。
理解 NLL 能解释一半「我明明没用了为什么还报错」——剩下的报错请继续读。

### 常见报错速查表

| 错误码 | 含义 | 典型修复 |
|--------|------|----------|
| E0382 | use after move | clone / 借用代替转移 / 重排逻辑 |
| E0502 | 同时可变与不可变借用 | 缩小借用范围（提前结束读） |
| E0499 | 同时两个可变借用 | 重构：让数据流串行化 |
| E0507 | 不能 move 出借用 | 用 clone 或返回拷贝 |
| E0597 | 借用活得比被借者久（悬垂） | 让数据与引用同生命周期 / 拥有数据 |
| E0106 | 缺生命周期标注 | 补 `'a`（见第四节） |

## 三、函数间的所有权流

```rust
// 吃掉所有权（消费型 API）
fn takes_ownership(s: String) { }

// 只读访问（最常用）：不拿走、不改，用完就还
fn borrows(s: &String) -> usize { s.len() }

// 可变借用：就地修改
fn appends(s: &mut String) { s.push('!') }

// 转移 + 返回（链式修改的惯用法）
fn transform(mut s: String) -> String { s.push_str("!!"); s }
```

> 【Java】参数传递在 Java 里全是「传引用的副本」。
> Rust 函数签名是文档：`String`（拿走）、`&String`（读）、`&mut String`（写）。
> 性能直觉：能用 `&` 绝不 clone，能用 `&mut` 绝不拿所有权——
> 但也别过度借用导致签名复杂，消费型 API（拿所有权）往往更清晰。

## 四、生命周期标注

生命周期标注**不改变任何行为**，只是帮编译器完成「引用间的相对关系」约束求解：

```rust
// 报错场景：返回的引用来自 a 还是 b？编译器无法证明它不会悬垂
// fn longest(a: &str, b: &str) -> &str { ... }   // ❌ E0106

// 标注：声明「返回值的生命周期不超过 a、b 中较短者」
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}
```

三条省略规则（记牢，90% 场景免标注）：

1. 每个输入引用参数独立生命周期
2. 只有一个输入引用 → 输出引用同它
3. 有 `&self` → 输出引用绑 self

```rust
fn first_word(s: &str) -> &str { ... }      // 规则2，无需标注
impl S { fn field(&self) -> &str { ... } }  // 规则3，无需标注
```

### struct 持有引用

```rust
struct Parser<'a> {          // Parser 借用外部数据，不能比数据活得久
    input: &'a str,
}
impl<'a> Parser<'a> {
    fn peek(&self) -> Option<char> { self.input.chars().next() }
}
```

> 拿不准时的工程决策：**struct 尽量拥有数据（String 而非 &str），
> 借用只在零拷贝热路径（协议解析）使用**。
> 【实战】rust-im 阶段 1 的解码器会返回借用 payload 的帧（零拷贝），
> 这是 `<'a>` 真正发光的场景。

### 'static

```rust
let s: &'static str = "编译进二进制的字面量";
```

`'static` = 不依赖任何局部作用域。字符串字面量、全局常量天然满足；
`tokio::spawn` 要求 `'static` 的原因见 [03-tokio/04](../03-tokio/04-任务管理与Channel.md)。
