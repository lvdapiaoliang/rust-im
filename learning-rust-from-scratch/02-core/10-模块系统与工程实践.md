# 10 - 模块系统、测试与工程实践

## 本章目标

掌握 crate/module 的可见性模型、单元测试与集成测试组织、
workspace 多 crate 工程化——为读懂 rust-im 的仓库结构铺路。

## 一、模块系统：与 Java 包的三大差异

Java 的可见性按「包层级」组织；Rust 是 **crate → module 树 + 显式 re-export**：

```rust
// src/lib.rs —— crate 根
mod network {                  // 私有模块（默认）
    pub mod tcp {              // pub 才对外可见
        pub struct Conn { pub id: u64, retries: u32 }   // 字段也要逐个 pub！

        impl Conn {
            pub fn new(id: u64) -> Self { Self { id, retries: 0 } }
            fn backoff(&self) -> u32 { self.retries }   // 私有方法
        }
    }
}

pub use network::tcp::Conn;    // re-export：调用方直接 use my_crate::Conn
```

可见性五档（对照 Java）：

| Rust | Java | 说明 |
|------|------|------|
| 私有（默认） | private | 仅本模块及子模块 |
| `pub(crate)` | 包内可见（无直接对应，近 package-private） | 本 crate 内任意位置 |
| `pub(super)` | — | 父模块 |
| `pub(in path)` | — | 指定路径内 |
| `pub` | public | 完全公开 |

> 关键思维：Rust 的默认是「私有，显式开放」。Java 程序员最初会觉得啰嗦，
> 但它带来的 API 面完全可控——**你的公开 API 就是你 `pub use` 出去的东西**，
> 内部重构不破坏调用方。

### 引用路径

```rust
use crate::network::tcp::Conn;    // 绝对路径（crate 根开始，推荐）
use super::sibling;                // 相对路径（父模块）
use self::inner;                   // 当前模块内
// 2018+ 惯例：外部 crate 直接 use tokio::sync::mpsc（不用 ::crate 前缀）
```

### 文件即模块

```
src/
├── lib.rs          # crate 根：mod 声明组织一切
├── network.rs      # mod network 的实现（或 src/network/mod.rs）
└── network/
    └── tcp.rs      # mod network::tcp
```

`lib.rs` 里只需 `pub mod network;`，文件位置自动映射模块树。

## 二、测试组织

### 单元测试：和实现放一起

```rust
// src/tcp.rs —— 测试就写在被测代码文件里（私有函数也能测！）
pub fn checksum(data: &[u8]) -> u16 { ... }

#[cfg(test)]                    // 编译产物里不包含测试代码
mod tests {
    use super::*;               // 引入父模块（被测代码）的一切

    #[test]
    fn checksum_empty_is_zero() {
        assert_eq!(checksum(&[]), 0);
    }

    #[test]
    #[should_panic(expected = "index")]
    fn out_of_range_panics() { ... }

    #[test]
    fn with_result() -> Result<(), String> {   // 返回 Err 即失败
        if 2 + 2 == 4 { Ok(()) } else { Err("数学坏了".into()) }
    }

    #[test]
    #[ignore = "需要真实网络"]                  // cargo test -- --ignored 单独跑
    fn integration_real_network() { ... }
}
```

### 集成测试：tests/ 目录

```
tests/
└── echo_test.rs      # 每个文件是独立 crate，只能访问公开 API（黑盒测试）
```

```rust
// tests/echo_test.rs
use im_transport::run_echo_client;    // 只能用 pub API —— 倒逼 API 设计合理

#[tokio::test]
async fn echo_works() { ... }
```

> 【Java】JUnit 的 @Test 思维直接平移，但有两个 Rust 特色：
> ① 单元测试与实现同文件可测私有函数（Java 要反射或包可见性技巧）；
> ② tests/ 目录天然黑盒，**它编译不过说明你的 API 不好用**——这是免费的 API 审查。
> 【实战】rust-im 的 echo 测试就是 `#[tokio::test]` + tests/ 集成测试双轨。

### 常用断言

```rust
assert_eq!(a, b, "自定义失败信息 {a}");
assert_ne!(a, b);
assert!(cond);
assert!(matches!(state, ConnState::Connected { .. }));   // 模式断言！
```

## 三、Workspace 多 crate 工程

```
rust-im/                     # workspace 根（只有 Cargo.toml，无 [package]）
├── Cargo.toml               # [workspace] + [workspace.dependencies]
└── crates/
    ├── im-protocol/         # 每个 crate 独立 [package]
    └── im-transport/
```

```toml
# 根 Cargo.toml 的关键段
[workspace]
members = ["crates/*"]                       # 实际要逐个列出
resolver = "3"

[workspace.dependencies]                     # 版本单一来源（SoV）
tokio = { version = "1", features = ["full"] }
im-protocol = { path = "crates/im-protocol" }  # 内部依赖用 path

# 子 crate 里：
# tokio.workspace = true      （继承版本与 features）
```

> 【Java】workspace ≈ Maven 多模块：统一构建/统一版本/共享 target 目录（省磁盘与编译时间）。
> **何时拆 crate**：编译边界（大 crate 拆小显著提速增量编译）、
> API 边界（pub(crate) 管不住的跨团队契约）、发布边界（SDK 要单独发版）。

## 四、其他工程实践速记

```rust
// 文档注释（/// 生成 rustdoc，支持示例测试）
/// 计算校验和。
///
/// # Examples
///
/// ```
/// assert_eq!(mycrate::checksum(&[1, 2]), 3);   // 文档里的代码会被 cargo test 执行！
/// ```
pub fn checksum(data: &[u8]) -> u16 { ... }

// 属性（编译期指令）
#[derive(Debug, Clone)]
#[allow(dead_code)]
#[cfg(feature = "tls")]        // 条件编译（feature gate）
#[non_exhaustive]              // enum/struct 不允许外部穷尽匹配——版本兼容武器

// 内部文档 //!（模块级说明，crate 根 lib.rs 开头那坨就是它）
```

```powershell
cargo test                    # 全部测试（单测+集成+文档测试）
cargo test -p im-protocol     # 只测一个 crate
cargo doc --open              # 生成文档
cargo clippy -- -W clippy::pedantic   # 严格 lint
cargo fmt                     # 格式化（省掉所有格式争论）
```
