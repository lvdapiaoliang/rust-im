# 08 - Rust Compiler Error Index（编译错误码索引）

> **原文**：<https://doc.rust-lang.org/error_codes/error-index.html>
> **规模**：700+ 个错误码（E0001–E0999），**不读，只查**
> **查法**：`rustc --explain E0382`（终端直接输出完整说明，无需打开浏览器）
> **中文**：无官方完整中译；**本页提供学习期高频错误码中文速查表**

## 一、错误码怎么用（3 分钟学会）

```powershell
# 方法 1：命令行解释（最快）
rustc --explain E0507

# 方法 2：网页（有完整示例代码）
# https://doc.rust-lang.org/error_codes/E0507.html

# 方法 3：编译错误输出里直接带链接（RustRover 里点击即跳）
```

> 【Java】类似 `javac` 的错误输出 + JLS 章节引用的合体，
> 但质量高得多：**每个错误码都有「错误现场 → 为什么 → 怎么修」三段式讲解**，
> 且大量给「这样做不对，应该那样做」的对照代码。
> 这是 Rust 学习曲线陡峭的补偿机制——**报错本身是最好的教材**。

## 二、错误码编号分区（按主题）

| 区段 | 主题 | 典型错误 |
|---|---|---|
| E0xxx | 杂项/内部 | E0001 不寻常的 switch 语句 |
| E03xx | **类型系统** | E0308 类型不匹配、E0384 不可变变量二次赋值 |
| E04xx | **定义/解析** | E0405 未找到 trait、E0432 import 不存在、E0463 找不到 crate |
| E05xx | **所有权/借用重灾区** | E0502/E0505/E0507/E0509/E0515/E0521/E0596/E0597/E0601/E0602 |
| E06xx | 类型与 trait（续） | E0609 字段不存在、E0658 unstable 特性 |
| E07xx | **2018+ 新增** | E0716 临时值被 drop、E0732 `#[must_use]` |
| E08xx | 近年新增 | E0801? 以官方索引为准（编号仍在增长） |

> ⚠️ 分区是大致规律，不是严格规则——**以搜索/索引页为准**。

## 三、高频错误码中文速查表（Java 工程师视角）

> 这是学习期 80% 报错的来源。每个码配一行「人话」+ 学习系列对应章节。
> 深入讲解见 [core/06 报错速查表](../../02-core/06-所有权借用生命周期.md)。

### 借用与所有权（E03xx/E05xx——最痛的 500 里）

| 码 | 官方标题（人话版） | 触发场景 | 修法 | 详解 |
|----|------|------|------|------|
| **E0382** | 值被移动后继续使用 | 把 String 传给函数后再 println | 传 `&s` 或 `clone()` | core/06 |
| **E0384** | 不可变变量二次赋值 | `let x=5; x=6;` | `let mut x` | basics/02 |
| **E0499** | 同一数据可变借用两次 | 连续两个 `&mut` 活跃 | 作用域拆分/重构 | core/06 |
| **E0502** | 借用的同时可变借用 | 先 `&mut v.push()` 再 `&v` | 借用结束再可变 | core/06 |
| **E0505** | 值被移动但仍有借用 | `let r=&s; drop(s);` | 限制生命周期/clone | core/06 |
| **E0507** | 不能移动出借用 | `*ref = owned_value` 部分移动 | `clone` 或 `std::mem::take` | core/06 |
| **E0596** | 不能借用不可变数据为可变 | `&x` 想变 `&mut x` | `mut` 声明或 RefCell | core/06,09 |
| **E0597** | 借用活得比被借者久 | 局部变量引用返回出去 | 返回值带生命周期/移动所有权 | core/06 |

### 类型系统

| 码 | 人话 | 修法 |
|----|------|------|
| **E0308** | 类型不匹配（最常见，原因五花八门） | 看错误里的 expected/found 对比 |
| **E0277** | trait 约束不满足（`doesn't implement Display`） | 实现 trait 或换类型/手动 Debug |
| **E0282** | 需要类型标注 | `let x: u32 = "5".parse()?` 的冒号 |
| **E0283** | 类型歧义（多个 impl 都可能） | 明确 turbofish `collect::<Vec<_>>()` |
| **E0509** | 不能移出 Drop 类型字段 | 借用或重构（Drop 类型=Java finalize 表亲，规则更严） |

### 模块与解析

| 码 | 人话 | 修法 |
|----|------|------|
| **E0432** | use 路径不存在 | 检查可见性（core/10 的五档可见性）/Cargo.toml 依赖 |
| **E0433** | use 的 crate 名不存在 | 依赖没声明或名字拼错 |
| **E0603** | 模块/项是私有的 | `pub(crate)`/`pub` 调整可见性 |
| **E0405** | 未找到 trait | 同 E0432 |
| **E0463** | 找不到 crate | `cargo add` 或检查 target/feature |

### 生命周期

| 码 | 人话 | 修法 |
|----|------|------|
| **E0106** | 缺少生命周期标注 | 三个省略规则覆盖不到——学习 core/06 的省略规则 |
| **E0623** | 生命周期不匹配 | 显式标注让编译器理解数据关系 |
| **E0700** | trait 生命周期不满足 | 引入新的生命周期参数 |

### 其他值得认识的

| 码 | 人话 |
|----|------|
| **E0716** | 临时值活不过引用——`let r = &foo().field;` 经典坑（tokio 篇 `&stream` 半包错误同源） |
| **E0713** | 新生命周期引入破坏老代码 |
| **E0658** | 用了 unstable 特性（阶段 8 io_uring 会遇到） |
| **E0601** | no_std 环境 println 不可用 |
| **E0133** | unsafe 操作没包 unsafe 块（Nomicon 入口） |
| **E0729** | 非 exhaustive match——新模式没处理（这正是 enum 状态机的保护机制，patterns/03） |

## 四、读错误信息的正确姿势（内功心法）

```
error[E0382]: borrow of moved value: `msg`
   --> src/main.rs:12:23          ← 第一站：位置
    |
10  |     process(msg);           ← 「值在这里被移动了」
    |             --- value moved here
11  |     process(&msg);          ← 「你还想用」
    |               ^^^ value borrowed here after move
    |
note: ...                        ← 第二站：编译器的解释
help: consider cloning the value ← 第三站：建议的修法
```

**三段式阅读法**：位置 → 原因 → 建议。Java 工程师习惯看第一行，
Rust 的黄金信息往往在 `note:` 和 `help:` 里。

## 五、配合工具

```powershell
cargo clippy        # 比 rustc 更「教练式」的 lint，很多错误在变成错误前被它拦截
cargo fix           # 自动修复机器可修的错误（迁移/低版本 API 等）
```
