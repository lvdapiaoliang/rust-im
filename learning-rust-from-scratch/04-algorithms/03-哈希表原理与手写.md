# 03 - 哈希表：从原理到手写（含一致性哈希预演）

## 本章目标

吃透哈希表的三要素（哈希函数、冲突处理、扩容策略），手写一个可用的 HashMap，
理解 LRU 的标准实现，为一致性哈希环（阶段 3）打底。

## 一、哈希表三要素

### 1. 哈希函数

```
key → hash → 桶下标（hash % 桶数 或 hash & (桶数-1)）
```

- Rust 标准库对整数用**乘法哈希**（wrapping_mul + 高位折叠），防连续 key 全撞车
- 对 String 用 **SipHash**：慢，但抗哈希碰撞 DoS 攻击（Java 8 之后也升级了类似策略）
- 高性能场景换 `ahash`（SIMD 加速，快 5~10 倍，不承诺抗 DoS）

> 【Java】HashMap 的链地址 + 红黑树化（链长 > 8）你已熟悉；
> Rust std 用**瑞士表**（swisstable，Google absl 的同款）：控制字节 SIMD 并行探测，
> 缓存友好，平均探测次数显著低于经典开放寻址。rustc 自己就是大受益者。

### 2. 冲突处理

| 策略 | 思路 | 代表 |
|------|------|------|
| 链地址 | 桶 = 链表/Vec，冲突追加 | Java HashMap |
| 开放寻址（线性/二次/双重） | 冲突就找下一个空位 | 瑞士表、Python dict |

### 3. 扩容再散列

```
负载因子 = 元素数 / 桶数，超过阈值（Rust: 7/8，Java: 0.75）→ 全量再散列
Rust 一次 rehash 到「刚好装下」的桶数；大表扩容瞬间有分配抖动
（高并发服务的解法：分片表渐进扩容、或直接上 DashMap）
```

## 二、手写 HashMap（分离链接版，教学最清晰）

```rust
const DEFAULT_BUCKETS: usize = 16;

pub struct MyHashMap<K, V> {
    buckets: Vec<Vec<(K, V)>>,
    len: usize,
}

impl<K: std::hash::Hash + Eq, V> MyHashMap<K, V> {
    pub fn new() -> Self {
        Self { buckets: Self::new_buckets(DEFAULT_BUCKETS), len: 0 }
    }

    fn new_buckets(n: usize) -> Vec<Vec<(K, V)>> {
        (0..n).map(|_| Vec::new()).collect()
    }

    fn bucket_idx(&self, key: &K) -> usize {
        use std::hash::{BuildHasher, Hasher};
        use std::collections::hash_map::DefaultHasher;
        let mut h = DefaultHasher::new();
        key.hash(&mut h);
        (h.finish() as usize) % self.buckets.len()
    }

    pub fn len(&self) -> usize { self.len }

    pub fn insert(&mut self, key: K, value: V) -> Option<V> {
        let idx = self.bucket_idx(&key);
        let bucket = &mut self.buckets[idx];
        for (k, v) in bucket.iter_mut() {
            if *k == key {
                let old = std::mem::replace(v, value);  // 原子换值，不 move 整个元组
                return Some(old);
            }
        }
        bucket.push((key, value));
        self.len += 1;
        if self.len > self.buckets.len() * 3 / 4 {      // 负载因子 0.75
            self.rehash();
        }
        None
    }

    pub fn get(&self, key: &K) -> Option<&V> {
        let idx = self.bucket_idx(key);
        self.buckets[idx].iter()
            .find(|(k, _)| k == key)
            .map(|(_, v)| v)
    }

    pub fn get_mut(&mut self, key: &K) -> Option<&mut V> { /* 同上可变版 */ }

    pub fn remove(&mut self, key: &K) -> Option<V> {
        let idx = self.bucket_idx(key);
        let bucket = &mut self.buckets[idx];
        // 优化点：remove 需要 key 比较 + 拿 value，注意 borrow 关系
        if let Some(pos) = bucket.iter().position(|(k, _)| k == key) {
            self.len -= 1;
            return Some(bucket.swap_remove(pos).1);
        }
        None
    }

    fn rehash(&mut self) {
        let old = std::mem::take(&mut self.buckets);    // 拿走旧桶（留空防借用冲突）
        self.buckets = Self::new_buckets(old.len() * 2);
        self.len = 0;
        for bucket in old {
            for (k, v) in bucket {
                self.insert(k, v);                       // 逐个重新散列
            }
        }
    }
}
```

四个 Rust 技法值得记住：

1. `std::mem::replace/take`：在不破坏借用的情况下「偷走」值——容器代码的常客
2. `swap_remove`：O(1) 删除（顺序无关时）
3. `position + swap_remove` 组合：查找删除两步走
4. rehash 用 take + 重建，避免 `&mut self` 自我嵌套借用

## 三、LRU 缓存：HashMap + 双向链表的标准组合（LC 146）

```rust
use std::collections::HashMap;
use std::rc::Rc;
use std::cell::RefCell;

/// 教学版 LRU（单线程 Rc/RefCell；生产用 HashMap + 侵入式链表或现成 lru crate）
struct LruCache {
    capacity: usize,
    map: HashMap<i32, Rc<RefCell<ListNode>>>,
    head: Option<Rc<RefCell<ListNode>>>,     // 头 = 最近使用
    tail: Option<Rc<RefCell<ListNode>>>,     // 尾 = 最久未用
}

struct ListNode {
    key: i32,
    value: i32,
    prev: Option<std::rc::Weak<RefCell<ListNode>>>,
    next: Option<Rc<RefCell<ListNode>>>,
}

impl LruCache {
    fn get(&mut self, key: i32) -> Option<i32> {
        let node = self.map.get(&key)?.clone();
        let v = node.borrow().value;
        self.detach(&node);
        self.push_front(node);
        Some(v)
    }
    // put / detach / push_front / evict 略——完整实现见 rust-im 阶段 3 练习
}
```

> **复杂度全 O(1) 的原理**：HashMap 负责「key → 链表节点」O(1) 定位，
> 双向链表负责「O(1) 移动到头 / O(1) 删尾」。
> 这是「两个数据结构各取所长」的典范——面试手写频率最高的组合。
> 【实战】rust-im 阶段 3 的服务端会话缓存、阶段 8 挂载盘目录缓存都用 LRU。

## 四、一致性哈希（分布式哈希的 cousin，阶段 3 预演）

普通哈希的问题：桶数变化（扩缩容）→ 几乎所有 key 重新映射 → 缓存全失效。

```
一致性哈希：把哈希空间看成一个环（0 ~ 2^64）
  服务器按 hash(ip) 放到环上
  key 按 hash(key) 顺时针找到第一台服务器
  节点增删只影响环上相邻区段的数据！
  虚拟节点：每台服务器映射几百个点，抹平数据倾斜
```

```rust
/// 一致性哈希环骨架（阶段 3 完整实现 + 虚拟节点 + 二分查找）
pub struct HashRing {
    ring: Vec<(u64, String)>,     // (hash, node) 有序数组
}

impl HashRing {
    pub fn get(&self, key: &str) -> &str {
        let h = simple_hash(key);
        // 二分找到第一个 hash >= h 的节点（环回绕到 0）
        let idx = self.ring.partition_point(|(nh, _)| *nh < h);
        &self.ring[idx % self.ring.len()].1
    }
}
```

> `partition_point`（二分）+ 有序数组 = O(log n) 路由，
> 这是 Redis Cluster / Memcached 客户端 / 分布式存储的通用方案。
> 【实战】rust-im 阶段 3 预留分布式路由，就是它 + 虚拟节点。
