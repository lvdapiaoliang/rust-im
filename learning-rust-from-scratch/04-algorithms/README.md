# 04 - 算法与数据结构（Rust 版）：学习路线

> 本系列的独特价值：**用 Rust 的所有权思维重新理解数据结构**。
> Java 里链表节点是 `Node { next: Node }` 随手写；
> Rust 里你会被所有权逼着直面「这些指针到底归谁」——
> 这恰恰是数据结构的本质。学完你会发现：**Rust 是学数据结构的最佳语言**。

## Rust 写数据结构的三条独特经验（先记在心里）

**经验一：链表是 Rust 的「新手坟场」，但值得死一次**

```rust
// Java 思维的直接翻译——编译不过！
struct Node<T> { value: T, next: Box<Node<T>> }        // 单链表 OK
// 但想写双向链表：
struct Node<T> { value: T, prev: Box<Node<T>>, next: Box<Node<T>> }  // ❌ 每个节点被两个所有者指向
// 你会被迫理解：双向链表的 prev/next 本质是「共享可变」，需要 Rc<RefCell<>> 或裸指针
```

> 结论：**生产代码用 `Vec`/`VecDeque`（连续内存，缓存友好），
> 双向链表只在需要 O(1) 中间删除时才考虑，且优先用现成 crate（如 intrusive-collections）**。

**经验二：借用检查器逼你把「谁在改数据」写成签名**

```rust
// 快排分区：Java 里随便传下标；Rust 里必须说清借用关系
fn partition(arr: &mut [i32], lo: usize, hi: usize) -> usize { ... }
//                                              ↑ 不传长度，切片自带；越界会在编译期被 push
```

**经验三：泛型 + trait 约束 = 数据结构一次写好，处处复用**

```rust
// 一个泛型小顶堆，u64 时间戳、String 消息都能装
struct MinHeap<T: Ord> { ... }
```
