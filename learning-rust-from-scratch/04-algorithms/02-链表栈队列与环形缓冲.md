## 一、链表：所有权的教学现场

### 单链表（能写，但要想清楚）

```rust
pub struct List<T> {
    head: Link<T>,
}

type Link<T> = Option<Box<Node<T>>>;

struct Node<T> {
    value: T,
    next: Link<T>,
}

impl<T> List<T> {
    pub fn new() -> Self { List { head: None } }

    pub fn push(&mut self, value: T) {           // 头插 O(1)
        let node = Box::new(Node { value, next: self.head.take() });
        self.head = Some(node);
        // take() 是链表代码的灵魂：把 Option 里的值 move 出来，留下 None
    }

    pub fn pop(&mut self) -> Option<T> {          // 头删 O(1)
        self.head.take().map(|node| {
            self.head = node.next;
            node.value
        })
    }
}

impl<T> Drop for List<T> {
    fn drop(&mut self) {
        // 防止递归 drop 溢出（长链表递归析构会栈溢出！）
        while let Some(_) = self.pop() {}
    }
}
```

三个 Rust 专属知识点：

1. `Option::take()`：链表操作的万能钥匙（拿走值、留 None、借用不冲突）
2. **递归 Drop 溢出**：默认 drop 是递归的，10 万元素的链表会栈溢出——必须手写迭代版
3. `Box` 的存在意义：递归类型必须堆上断开（核心篇 09）

### 双向链表：被迫面对真实复杂度

```rust
use std::rc::{Rc, Weak};
use std::cell::RefCell;

struct Node<T> {
    value: T,
    prev: Option<Weak<RefCell<Node<T>>>>,   // Weak 防循环引用泄漏！
    next: Option<Rc<RefCell<Node<T>>>>,
}
// 每次访问都要 .borrow_mut()，运行时借用检查……
// 真实感受：用 Rust 写双向链表 = 把 Java 的隐式自由变成显式契约
```

> 工程结论（也是面试标准答案）：**Rust 里需要链表语义时，
> 90% 场景 `VecDeque`（环形数组双端队列）更快更简单；
> 真要 O(1) 中间删除且持有迭代器，用侵入式链表（intrusive-collections）**。

## 二、栈：两个 Vec 就能模拟一切

```rust
pub struct MinStack<T: Ord + Clone> {
    data: Vec<T>,
    mins: Vec<T>,       // 辅助栈：栈顶永远是当前最小值（LC 155）
}

impl<T: Ord + Clone> MinStack<T> {
    pub fn push(&mut self, v: T) {
        let new_min = self.mins.last().map_or(v.clone(), |m| m.min(v.clone()));
        self.mins.push(new_min);
        self.data.push(v);
    }
    pub fn pop(&mut self) -> Option<T> { self.mins.pop(); self.data.pop() }
    pub fn min(&self) -> Option<&T> { self.mins.last() }
}

// 单调栈经典应用：下一个更大元素（每日温度 LC 739）
pub fn daily_temperatures(temps: &[i32]) -> Vec<usize> {
    let mut ans = vec![0; temps.len()];
    let mut stack: Vec<usize> = vec![];          // 存下标，值单调递减
    for (i, &t) in temps.iter().enumerate() {
        while let Some(&j) = stack.last() {
            if temps[j] >= t { break; }
            stack.pop();
            ans[j] = i - j;                       // 找到 j 的「下一个更热天」
        }
        stack.push(i);
    }
    ans
}
```

## 三、队列与环形缓冲（本章主角）

队列用数组实现的唯一正确形态就是**环形缓冲**（ring buffer / circular buffer）：

```
容量 8，head=读位置，tail=写位置，len 计数（head/tail 二选一 + len）

    [ A ][ B ][ C ][   ][   ][   ][   ][   ]
           ↑ head=1        tail=4 →（写这里）
push 到尾部，pop 从头部：都是 O(1)，内存零搬移
tail 到 7 后下一个写回 0 —— 环！

判满：len == capacity
判空：len == 0
```

> 为什么不用「head == tail 判空」：那样「满」和「空」无法区分（都要留一格或用计数器）。
> 用 `len` 计数最直观。

### 手写 RingBuffer（rust-im 阶段 1/2 的核心结构原型）

```rust
/// 定容环形缓冲：字节流的接收缓冲（教学版，容量编译期固定）
pub struct RingBuffer<const N: usize> {
    buf: [u8; N],
    head: usize,   // 下一个读位置
    len: usize,    // 当前有效字节数
}

impl<const N: usize> RingBuffer<N> {
    pub fn new() -> Self {
        Self { buf: [0; N], head: 0, len: 0 }
    }

    pub fn len(&self) -> usize { self.len }
    pub fn is_empty(&self) -> bool { self.len == 0 }
    pub fn is_full(&self) -> bool { self.len == N }

    /// 尾部写入，返回实际写入字节数（可能因满而部分写入）
    pub fn write(&mut self, data: &[u8]) -> usize {
        let mut written = 0;
        for &b in data {
            if self.is_full() { break; }
            let tail = (self.head + self.len) % N;   // 环形寻址的核心公式
            self.buf[tail] = b;
            self.len += 1;
            written += 1;
        }
        written
    }

    /// 头部读出最多 max_out 字节到 out，返回实际读取数
    pub fn read(&mut self, out: &mut [u8]) -> usize {
        let n = out.len().min(self.len);
        for slot in out.iter_mut().take(n) {
            *slot = self.buf[self.head];
            self.head = (self.head + 1) % N;          // 读指针转圈
        }
        self.len -= n;
        n
    }

    /// 窥视不消费（协议解码器「先看够不够一帧」的关键操作）
    pub fn peek(&self, out: &mut [u8]) -> usize {
        let n = out.len().min(self.len);
        for (i, slot) in out.iter_mut().enumerate().take(n) {
            *slot = self.buf[(self.head + i) % N];
        }
        n
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn wraparound_works() {
        let mut rb = RingBuffer::<4>::new();
        assert_eq!(rb.write(b"abcdef"), 4);      // 只装得下 4 个
        assert_eq!(rb.read(&mut [0; 2]), 2);     // 读出 "ab"
        assert_eq!(rb.write(b"gh"), 2);          // 尾部绕回 0、1 槽位
        let mut out = [0u8; 4];
        assert_eq!(rb.read(&mut out), 4);
        assert_eq!(&out, b"cdef");               // 顺序保持！
    }
}
```

**工程优化路线**（rust-im 阶段 1 会做）：

1. `% N` 换位运算 `& (N - 1)`（N 取 2 的幂）
2. 泛型化 `RingBuffer<T, const N: usize>` + 可增长版本
3. **「连续段优化」**：环形缓冲有「尾绕回头」的两段问题，批量 IO 时用
   `VecDeque` 或 `bytes::BytesMut` 的 contiguous slices 避免逐字节循环
4. 对比基准：手写 vs `VecDeque<u8>` vs `BytesMut`（学习目标：理解为什么生产用 BytesMut）

### VecDeque：标准库的环形双端队列

```rust
use std::collections::VecDeque;
let mut dq: VecDeque<i32> = VecDeque::with_capacity(64);
dq.push_back(1); dq.push_front(0);      // 两端 O(1)
dq.pop_front(); dq.pop_back();
dq.as_slices();                          // 拿到（最多）两个连续段——批量 IO 用
```

> 【Java】ArrayDeque 就是环形缓冲；Rust VecDeque 同源。
> 【实战】rust-im 计划：接收缓冲用手写 RingBuffer（学习），
> 生产路径直接 `BytesMut`（tokio 生态的缓冲标准）。

## 四、环形缓冲的第二人生：滑动窗口

```
发送窗口（IM 可靠传输的核心）本质就是一个带序号的环形缓冲：

seq:      0  1  2  3  4  5
状态：  [ACK][ACK][等][发][可][可]
                        ↑ 窗口右沿：可以继续发
         ↑ 窗口左沿：最老的未确认

收到 ack=2 → 左沿右移 2 → 窗口滑出 2 个新槽位
超时未 ack → 从左沿重传
```

阶段 2 的 `SendWindow` 就是 RingBuffer + 定时重传的组合——
一个数据结构吃下 IM 消息可靠性的半壁江山。
