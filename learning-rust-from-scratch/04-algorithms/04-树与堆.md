## 一、二叉搜索树（BST）：快速过一遍 + Rust 一课

```rust
// Rust 的一课：递归类型 + Box（你已经会了）
struct BstNode {
    value: i64,
    left: Option<Box<BstNode>>,
    right: Option<Box<BstNode>>,
}

impl BstNode {
    fn insert(&mut self, v: i64) {
        let target = if v < self.value { &mut self.left } else { &mut self.right };
        match target {
            None => *target = Some(Box::new(BstNode { value: v, left: None, right: None })),
            Some(node) => node.insert(v),
        }
    }

    fn contains(&self, v: i64) -> bool {
        match v.cmp(&self.value) {
            std::cmp::Ordering::Equal => true,
            std::cmp::Ordering::Less => self.left.as_ref().is_some_and(|n| n.contains(v)),
            std::cmp::Ordering::Greater => self.right.as_ref().is_some_and(|n| n.contains(v)),
        }
    }
}
```

- BST：查找/插入平均 O(log n)，**最坏 O(n)（退化为链表）**
- 平衡树（AVL/红黑树）通过旋转维持 O(log n)：`BTreeMap` 就是 B 变体（缓存友好的多路树）
- 面试只需讲清「为什么需要平衡 + 旋转的大致思想」；手撕红黑树不在必考范围

> 【Java】TreeMap = 红黑树；Rust BTreeMap = B 树（节点多个键，更矮更缓存友好）。
> 有序需求才用它们，哈希足够时永远 HashMap。

## 二、堆：完全二叉树活在数组里

**核心洞见：完全二叉树不需要指针！子节点下标算出来。**

```
数组：      [10, 8, 9, 3, 5, 6]
下标：       0  1  2  3  4  5

i 的左孩子 = 2i+1，右孩子 = 2i+2，父节点 = (i-1)/2

        10            ← 大顶堆：父 >= 子（只保证这个，不是全排序！）
       /  \
      8    9
     / \  /
    3  5 6
```

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| push | O(log n) | 尾部插入 + 上浮（sift_up） |
| pop | O(log n) | 头部弹出 + 尾元素补位 + 下沉（sift_down） |
| peek | O(1) | 看堆顶 |
| 建堆 | O(n) | 从无序数组自底向上堆化（Floyd，不是 O(n log n)！） |

### 手写 MinHeap

```rust
pub struct MinHeap<T: Ord> {
    data: Vec<T>,
}

impl<T: Ord> MinHeap<T> {
    pub fn new() -> Self { Self { data: Vec::new() } }
    pub fn len(&self) -> usize { self.data.len() }
    pub fn is_empty(&self) -> bool { self.data.is_empty() }
    pub fn peek(&self) -> Option<&T> { self.data.first() }

    pub fn push(&mut self, item: T) {
        self.data.push(item);
        self.sift_up(self.data.len() - 1);
    }

    pub fn pop(&mut self) -> Option<T> {
        if self.data.is_empty() { return None; }
        let last = self.data.pop()?;          // 先取尾
        match self.data.first_mut() {
            None => Some(last),               // 原来只有一个元素
            Some(top) => {
                let min = std::mem::replace(top, last);  // 尾补位，换出堆顶
                self.sift_down(0);
                Some(min)
            }
        }
    }

    fn sift_up(&mut self, mut i: usize) {
        while i > 0 {
            let parent = (i - 1) / 2;
            if self.data[i] < self.data[parent] {
                self.data.swap(i, parent);    // 逆序就交换（比父小就上浮）
                i = parent;
            } else { break; }
        }
    }

    fn sift_down(&mut self, mut i: usize) {
        let n = self.data.len();
        loop {
            let (l, r) = (2 * i + 1, 2 * i + 2);
            let mut smallest = i;
            if l < n && self.data[l] < self.data[smallest] { smallest = l; }
            if r < n && self.data[r] < self.data[smallest] { smallest = r; }
            if smallest == i { break; }
            self.data.swap(i, smallest);
            i = smallest;
        }
    }
}
```

### 标准库版本

```rust
use std::collections::BinaryHeap;
use std::cmp::Reverse;

// BinaryHeap 是大顶堆；小顶 = Reverse 包装
let mut h: BinaryHeap<Reverse<u64>> = BinaryHeap::new();
h.push(Reverse(5));
let Reverse(min) = h.pop().unwrap();

// 自定义结构体：要么实现 Ord，要么用 BinaryHeap::from / peek_mut + Reverse
#[derive(PartialEq, Eq)]
struct Task { deadline: u64, name: String }
impl Ord for Task {
    fn cmp(&self, other: &Self) -> std::cmp::Ordering {
        self.deadline.cmp(&other.deadline)   // 【经典坑】先比较派生字段
        // 推荐：other.deadline.cmp(&self.deadline) —— 需要小顶语义时直接反写
    }
}
impl PartialOrd for Task { fn partial_cmp(&self, o: &Self) -> Option<std::cmp::Ordering> { Some(self.cmp(o)) } }
```

> Ord/PartialOrd 实现的坑：`derive(PartialOrd)` 要求先 `derive(PartialEq)`，
> 且**自反性/传递性/一致性违约会让堆逻辑错乱**（还能 UB 相关）——
> 永远用 `#[derive(PartialEq, Eq, PartialOrd, Ord)]`，手工实现只在自定义排序时写。

## 三、场景一：定时器管理（rust-im 心跳/重传的地基）

```rust
/// 最小堆定时器：deadline 最近的任务永远在堆顶
struct TimerEntry {
    deadline: std::time::Instant,
    callback: Box<dyn FnOnce() + Send>,      // 到期执行
}

struct TimerWheel {
    heap: BinaryHeap<Reverse<(std::time::Instant, u64)>>,   // (deadline, id)
    // 实际实现用 (Instant, id) 保证 Ord 稳定（Instant 相同也能比较）
}

// tick 循环：
// while let Some(&Reverse((deadline, _))) = heap.peek() {
//     if deadline > now { break; }         // 堆顶还没到期
//     pop → 执行/重注册
// }
// sleep(堆顶 - now) —— 永远只睡到下一个到期时刻（对比：轮询扫描全表 O(n)）
```

**进阶预告（阶段 2）**：定时器多到百万级时，堆的 O(log n) 也嫌贵——
**哈希定时轮（Hierarchical Timing Wheel）**把插入降到 O(1)
（Kafka/Netty 同款）。rust-im 阶段 2 手写它，这是本系列后续的高光章节。

## 四、场景二：Top-K 与 P99（压测的核心统计）

```rust
/// 流式 Top-K：维护大小为 K 的小顶堆
/// 堆顶是「当前第 K 大」，比它大的都能挤进来
pub fn top_k(nums: impl Iterator<Item = u64>, k: usize) -> Vec<u64> {
    let mut heap: BinaryHeap<Reverse<u64>> = BinaryHeap::new();
    for n in nums {
        if heap.len() < k {
            heap.push(Reverse(n));
        } else if let Some(Reverse(&top)) = heap.peek() {
            if n > *top {                    // 比当前第 K 大还大
                heap.pop();
                heap.push(Reverse(n));
            }
        }
    }
    heap.into_sorted_vec().into_iter().map(|Reverse(v)| v).collect()
}

// P99 延迟：本质就是 Top-1% 的边界值
// 更专业的工具：HdrHistogram（对数桶，固定内存，rust 有 hdrhistogram crate）
// 【实战】rust-im 的 im-bench 用它统计 P50/P90/P99/P999
```

为什么不用排序？n 条延迟数据排序 O(n log n) + 全量内存；
堆只要 O(n log k) + O(k) 内存——**流式场景（数据不能全存）唯一解**。
