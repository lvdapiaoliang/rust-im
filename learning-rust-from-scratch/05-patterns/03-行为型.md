# 03 - 行为型模式：状态机、观察者、责任链与 Actor

## 本章目标

掌握 Rust 形态的行为型模式。这些模式恰好是 IM 业务的骨架——
每节都直接对应 rust-im 的某个模块。

## 一、状态模式：enum + match（Rust 的招牌）

```rust
/// 连接生命周期状态机：非法状态转移不可能发生
#[derive(Debug, PartialEq)]
enum ConnState {
    Idle,
    Connecting { attempt: u32 },
    Handshaking { nonce: u64 },
    Online { session: u64 },
    Backoff { until: std::time::Instant },
    Closed,
}

impl ConnState {
    /// 转移函数：返回新状态或转移错误——用类型系统表达「这条边不存在」
    fn on_event(self, ev: Event) -> Result<Self, TransitionError> {
        use ConnState::*;
        match (self, ev) {
            (Idle, Event::Connect) => Ok(Connecting { attempt: 1 }),
            (Connecting { attempt }, Event::Connected(n)) => Ok(Handshaking { nonce: n }),
            (Connecting { attempt }, Event::Timeout) if attempt < 3 => {
                Ok(Connecting { attempt: attempt + 1 })    // 守卫：最多重试 3 次
            }
            (Connecting { .. }, Event::Timeout) => Ok(Backoff { until: backoff_time() }),
            (Handshaking { nonce }, Event::AuthOk(session)) => Ok(Online { session }),
            (Online { .. }, Event::Disconnect) => Ok(Backoff { until: backoff_time() }),
            (Backoff { until }, Event::TimerFired) => Ok(Connecting { attempt: 1 }),
            (s, e) => Err(TransitionError::Invalid { from: s, event: e }),
        }
    }
}
```

**三重保险**：

1. **穷尽性**：新增状态/事件 → 所有 match 编译报错 → 不可能漏处理
2. **守卫**：`if attempt < 3` 直接写在模式里
3. **非法转移是类型错误**：`TransitionError::Invalid` 而不是静默忽略

> 【Java】GoF 状态模式 = State 接口 + 每状态一个类；
> Rust 的 enum 版**数据跟着状态走**（`Online { session }` 只有在线状态才有 session 字段），
> 不可能「离线状态里读 session」——Java 版做不到这一点。
> 【实战】rust-im 的握手协议、重连管理都是这个形态（阶段 2）。

## 二、观察者/发布订阅：channel 就是观察者

```rust
/// GoF 观察者的现代形态：订阅者持有 channel，发布者只管投递
use tokio::sync::broadcast;

pub struct EventBus {
    tx: broadcast::Sender<Event>,         // 事件源
}

#[derive(Clone, Debug)]
pub enum Event {
    UserOnline(u64),
    UserOffline(u64),
    Message { from: u64, to: u64 },
}

impl EventBus {
    pub fn new(capacity: usize) -> Self {
        let (tx, _) = broadcast::channel(capacity);
        Self { tx }
    }
    pub fn subscribe(&self) -> broadcast::Receiver<Event> {
        self.tx.subscribe()                // 每个订阅者独立游标
    }
    pub fn publish(&self, ev: Event) {
        let _ = self.tx.send(ev);          // 无订阅者时忽略错误
    }
}

// 订阅端（观察者）：
let mut rx = bus.subscribe();
tokio::spawn(async move {
    loop {
        match rx.recv().await {
            Ok(Event::UserOnline(id)) => println!("{id} 上线"),
            Ok(_) => {}
            Err(broadcast::error::RecvError::Lagged(n)) => {
                // 观察者模式与 channel 的合流点：慢消费者显式处理丢失
            }
            Err(_) => break,
        }
    }
});
```

**三种观察者形态选型**：

| 形态 | 语义 | rust-im 用途 |
|------|------|--------------|
| `broadcast` | 广播、可丢（Lagged） | 在线状态、事件总线 |
| `mpsc` | 单消费者、不丢（背压） | 消息下发（每连接一个） |
| 回调 `Box<dyn Fn(Event)>` | 同步、侵入式 | SDK 给 C 端的事件通知（阶段 6） |

> 【Java】Listener 列表 + `listeners.forEach(l -> l.onEvent(e))` 的隐式问题：
> 回调里抛异常炸谁？回调里再注册观察者（ConcurrentModificationException）？
> channel 版把这些问题变成显式的队列语义——**观察者模式在 Rust 的正名是「消息传递」**。

## 三、责任链：处理管线

```rust
/// 服务端入站包处理管线：解码 → 鉴权 → 限流 → 业务路由
/// 每层决定「继续传递」或「拦截」
enum Verdict {
    Continue(Frame),
    Intercept(Response),       // 短路：直接回包
}

trait FrameStage {
    fn process(&self, frame: Frame) -> Verdict;
}

struct Auth { tokens: TokenStore }
impl FrameStage for Auth {
    fn process(&self, frame: Frame) -> Verdict {
        if frame.is_authed() { Verdict::Continue(frame) }
        else { Verdict::Intercept(Response::unauthorized()) }
    }
}

struct RateLimit { /* 令牌桶 */ }
struct Router { sessions: SessionTable }

/// 责任链的执行器：类型化的流水线
fn run_chain(stages: &[&dyn FrameStage], mut frame: Frame) -> Option<Response> {
    for stage in stages {
        match stage.process(frame) {
            Verdict::Continue(f) => frame = f,
            Verdict::Intercept(resp) => return Some(resp),   // 短路
        }
    }
    None    // 全部通过 → 业务处理
}
```

> 【Java】Servlet Filter / Spring Interceptor / Netty Pipeline 都是它。
> Rust 版的进步：`Verdict` 枚举让「拦截 vs 放行」成为显式类型；
> tower 的 `Service` + `Layer` 把这个模式做成了通用中间件协议（同构于 axum 生态）。
> 【实战】rust-im 阶段 3 网关的入站处理就是这条链。

## 四、Actor：模式之王（tokio 篇的呼应）

```rust
/// Actor = 状态（私有）+ 邮箱（channel）+ 行为（loop + match）
/// 它同时是：并发模型（无锁共享）、观察者（消息驱动）、命令模式（消息即命令）
pub struct TimerActor {
    timers: BinaryHeap<Reverse<(Instant, u64)>>,   // 私有状态：堆（算法篇 04！）
}

pub enum TimerMsg {
    Schedule { deadline: Instant, id: u64 },
    Cancel { id: u64 },
}

impl TimerActor {
    /// 唯一的运行入口：独占 self，外界只能发消息
    pub async fn run(mut self, mut rx: mpsc::Receiver<TimerMsg>) {
        loop {
            let next = self.timers.peek().map(|Reverse((d, _))| *d);
            tokio::select! {
                msg = rx.recv() => match msg {
                    Some(TimerMsg::Schedule { deadline, id }) =>
                        self.timers.push(Reverse((deadline, id))),
                    Some(TimerMsg::Cancel { id }) =>
                        self.timers.retain(|Reverse((_, tid))| *tid != id),
                    None => break,                     // 所有 handle drop → 优雅退出
                },
                _ = tokio::time::sleep_until(next.unwrap_or_else(|| far_future())) => {
                    let Reverse((_, id)) = self.timers.pop().unwrap();
                    self.fire(id);
                }
            }
        }
    }
    fn fire(&mut self, id: u64) { /* 触发回调/发消息 */ }
}
```

这个 40 行的 Actor 同时用到了：堆（算法篇）、select（tokio 篇）、
状态私有化（所有权）、消息传递（观察者）、enum 命令（命令模式）——
**rust-im 全部知识的汇合点**。

## 五、快速过：剩下的小模式

```rust
/// 空对象（Null Object）：Option 的日常
fn greet(name: Option<&str>) {
    let name = name.unwrap_or("匿名用户");    // None 不是错误，是合法语义
}

/// 模板方法：trait 默认方法
trait Pipeline {
    fn before(&mut self) {}                  // 钩子（默认空实现）
    fn run(&mut self) {                      // 模板：固定骨架
        self.before();
        self.execute();
        self.after();
    }
    fn execute(&mut self);                   // 抽象步骤（必须实现）
    fn after(&mut self) {}
}

/// 备忘录：Clone + serde（序列化快照）
impl Session {
    fn snapshot(&self) -> SessionSnapshot { self.clone().into() }   // 存档
    fn restore(&mut self, s: SessionSnapshot) { *self = s.into(); }
}

/// 策略：闭包（轻量）或 trait 对象（重量）
fn retry_with(strategy: impl Fn(u32) -> Duration, ...) { ... }
retry_with(|n| Duration::from_millis(100 * 2u64.pow(n)), ...);   // 指数退避闭包
```
