# 02 - 创建型与结构型模式

## 本章目标

Builder 的类型化进阶、装饰器（Rust 零成本抽象的招牌菜）、适配器、门面、组合模式。

## 一、适配器：From/Into 就是它

```rust
/// 适配器：让不兼容的接口协作。Rust 把它做成了转换 trait 全家桶
let s: String = "hello".into();              // &str → String
let bytes: Vec<u8> = s.clone().into();       // String → Vec<u8>
let num: u64 = u8::from(42u8);               // 无损提升

// 自定义适配器：让旧接口适配新 trait
struct LegacyDb { /* 老代码，不能改 */ }
impl LegacyDb {
    fn query_raw(&mut self, sql: &str) -> Vec<Vec<String>> { ... }
}

// 新系统想要的结构化接口：
trait UserStore {
    fn get_user(&mut self, id: u64) -> Option<User>;
}

// 适配器：包一层，翻译接口（GoF 原味，只是 Rust 版更轻）
struct LegacyAdapter { inner: LegacyDb }
impl UserStore for LegacyAdapter {
    fn get_user(&mut self, id: u64) -> Option<User> {
        let rows = self.inner.query_raw(&format!("SELECT ... WHERE id={id}"));
        rows.into_iter().next().map(|r| User { name: r[0].clone(), .. })
    }
}
```

> 【Java】和 Adapter 完全同构；差异是 Rust 的 From/Into 标准化了一半场景
> （Java 得自己想方法名叫 toX 还是 fromX）。

## 二、装饰器：泛型组合的零成本抽象（本章主角）

需求流：给读数据流加缓冲、加压缩、加解密——层层包裹不改接口。

```rust
/// 标准库示例先行：BufReader 就是 InputStream 包装流的 Rust 版
use std::io::{BufReader, BufWriter, Read};
let f = std::fs::File::open("data.bin")?;
let mut reader = BufReader::new(f);          // File → BufReader<File>
// BufReader<T: Read> 自身也实现 Read —— 可继续包！

/// 手写一个 LineCounter 装饰器：统计读过的行数
struct LineCounter<R> {
    inner: R,
    lines: u64,
}

impl<R: Read> Read for LineCounter<R> {       // 装饰器：实现同接口 + 持有内层
    fn read(&mut self, buf: &mut [u8]) -> std::io::Result<usize> {
        let n = self.inner.read(buf)?;        // 委托内层
        self.lines += buf[..n].iter().filter(|&&b| b == b'\n').count();
        Ok(n)
    }
}

impl<R: Read> LineCounter<R> {
    fn lines_read(&self) -> u64 { self.lines }
}

// 组合（每层都是普通类型，编译期全部内联展开）：
let f = std::fs::File::open("app.log")?;
let mut reader = LineCounter { inner: BufReader::new(f), lines: 0 };
let mut out = String::new();
reader.read_to_string(&mut out)?;
// reader.lines_read() —— 装饰器状态可查询
```

**与 Java 装饰器的关键差异**：

| | Java `new BufferedReader(new FileReader(f))` | Rust `BufReader::new(f)` |
|---|---|---|
| 分发 | 虚调用（每层一次动态分派） | **编译期单态化，全部内联**（零成本） |
| 类型 | FileReader「消失」在 BufferedReader 里 | 类型就是 `BufReader<File>`，精确可追 |
| 数量限制 | 类型不限制层级 | 泛型嵌套写出来很长（`BufReader<LineCounter<File>>`） |

> 【实战】rust-im 传输层的目标形态：
> `Framed<TlsStream<BufStream<TcpStream>>, Codec>`——
> 字节流→缓冲→TLS→帧，四层装饰，每层一个职责，零虚调用。
> （tokio-util 的 Framed 正是这个模式的工业实现。）

**装饰器的另一副面孔：trait 组合（行为装饰）**

```rust
// 不包装 IO，而是包装「处理逻辑」——中间件！
trait Handler {
    async fn handle(&self, req: Request) -> Response;
}

struct Logging<H: Handler> { inner: H }          // 泛型持有下一层
impl<H: Handler> Handler for Logging<H> {
    async fn handle(&self, req: Request) -> Response {
        let start = Instant::now();
        let resp = self.inner.handle(req).await;  // 委托
        tracing::info!("{} {} {} {:?}", req.method, req.path, resp.status, start.elapsed());
        resp
    }
}
// tower::Service 的洋葱模型 = 这个模式的完全体（axum/tonic 生态的地基）
```

## 三、门面：模块 + re-export

```rust
/// 门面：复杂子系统收口成窄接口。Rust 的实现是「模块可见性 + pub use」
// lib.rs —— 子系统们
mod handshake;        // 内部细节全部私有
mod codec;
mod heartbeat;
mod reconnect;

/// 门面层：调用方只需要这一个类型和三个方法
pub struct Client { /* 组合私有子系统 */ }

impl Client {
    pub fn connect(addr: &str) -> Result<Self, Error> { ... }
    pub fn send(&self, msg: &str) -> impl Future<Output = Result<(), Error>> + '_ { ... }
    pub fn close(self) -> impl Future<Output = ()> { ... }
}

// 收口 re-export：调用方的 use 路径最短
pub use error::{Error, Result};
pub mod error;
```

> 【Java】Facade 类需要专门写；Rust 的可见性系统天然支持
> 「实现藏进私有模块，门面是唯一的 pub」。
> **判断标准：tests/ 集成测试 import 的路径就是你的门面质量**
> ——如果测试要 `use crate::handshake::internal::tls::Config`，门面就失败了。

## 四、组合模式：树形结构的自然表达

```rust
/// 组合：部分与整体统一接口。文件系统 / UI 树 / 消息路由树
enum Node {
    Leaf(Message),
    Group { name: String, children: Vec<Node> },      // 递归 Vec，不需要 Box！
}

impl Node {
    /// 统一的遍历接口：叶子执行，组递归
    fn deliver(&self) -> usize {
        match self {
            Node::Leaf(msg) => { send(msg); 1 }
            Node::Group { children, .. } => children.iter().map(Node::deliver).sum(),
        }
    }
}
```

> 【Java】GoF 组合要抽象 Component 接口 + Leaf/Composite 两实现；
> Rust 的 enum **就是**组合模式：变体即子类，match 即多态，且穷尽性检查
> 保证你加了变体不会漏处理任何分支。
> 【实战】挂载盘（阶段 8）的目录树、群消息的扇出树都是这个形态。

## 五、享元与代理：一行话模式（知道即可）

- **享元（Flyweight）**：`Arc<T>` 共享不可变数据 + `Clone` 廉价复制句柄，
  rust-im 的 `Bytes`（共享缓冲区切片）是教科书实现
- **代理（Proxy）**：智能指针 `Deref` 天然代理；访问控制代理写 struct 包一层
  （`Lazy<T>`、`ArcSwap`、连接池 `PoolConn` 都是代理家族）
